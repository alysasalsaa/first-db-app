📝 Retrospection
What use cases can you see for using IndexedDB in your frontend apps?
Offline-first apps (cached content, drafts), large datasets that exceed localStorage limits, shopping cart persistence, user preferences synced across tabs, form draft auto-save, and temporary staging areas for data fetched from an API before processing.
What advantages and disadvantages does IndexedDB have over file or localStorage?
Advantages: Supports structured data (objects, arrays), much larger storage quotas, transaction support, indexes for fast queries, and async API that won't block the main thread.
Disadvantages: More complex API than localStorage, no SQL-like query language, not shareable across devices, and data is lost if the user clears browser storage.
What criteria might you use to determine if IndexedDB is right for your app?
IndexedDB is a good fit when data is structured and relational, exceeds ~5MB, needs to persist across sessions without a server, or when offline support is required. It's less suitable for simple key-value flags (use localStorage), server-synced data that needs security, or apps that must support very old browsers. The right answer depends on data size, structure, offline needs, and how often data changes.
